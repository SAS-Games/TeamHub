# TeamHub Meeting Notes

Use this template for the generated Markdown. Omit a section only when the transcript contains no relevant information, except for **Open questions and gaps**, which should identify important missing or unclear details.

## Output structure

1. `# Meeting notes: <meeting title>`
2. A compact metadata table containing Date, Participants, and Purpose. Use `Not stated` when the transcript does not provide a value.
3. `## Executive summary` with two to five concise bullets.
4. `## Decisions` as bullets. Clearly label decisions that still require confirmation.
5. `## Action items` as a Markdown table with Action, Owner, Due date, and Status columns. Never invent an owner or due date; use `Unassigned` or `Not stated`.
6. `## Discussion notes`, grouped by topic rather than by speaker.
7. `## Risks and dependencies`.
8. `## Open questions and gaps`.

## Writing rules

- Prefer clear, concise business language.
- Preserve names, project names, ticket IDs, dates, and numbers exactly as stated.
- Merge repeated discussion without losing disagreements or uncertainty.
- Do not include conversational filler, unsupported conclusions, or information outside the transcript.
- If the user asks to revise existing notes, keep the same structure unless they explicitly request another format.
